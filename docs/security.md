# 安全说明

本文描述 Milestone 3 已实现的安全边界。在线更新器与发行签名属于 Milestone 4，仍需单独威胁审查，不能自动继承“已完成”状态。

## 凭据保护

- 密码、私钥内容和私钥口令序列化后使用 Windows DPAPI `User` scope 加密，密文保存在所选数据根目录的 `vault` 中。
- SQLite 只保存凭据引用，不包含密码、私钥或口令字段。
- 解密后的 `StoredCredential` 在 Rust 中实现 `ZeroizeOnDrop`；SSH 私钥由纯 Rust 传输层在内存中解析和签名，不创建明文私钥临时文件。
- DPAPI 密文绑定当前 Windows 用户安全上下文。把数据目录复制到其他 Windows 用户或其他电脑后，不应期望凭据仍可解密；需要重新输入或导入。
- 应用不把凭据、原始私钥、口令或完整凭据载荷写入日志和错误消息。

## SSH 主机身份

- 首次连接只检查并展示服务器主机密钥，必须由用户明确批准后才能保存信任。
- 保存的内容包括算法、原始公钥和 OpenSSH 风格的 SHA-256 指纹。
- 后续连接在发送密码或私钥签名前比较指纹。发生变化时显示期望值和实际值并终止连接，不会静默接受新密钥。
- 工具使用现代纯 Rust SSH 实现，支持密码和带口令 OpenSSH 私钥；认证、命令、日志和传输均有超时、输出/大小上限和取消语义。

## 工作流、脚本与恢复点

- 工作流只组合已经受控的任务、日志和 SFTP 服务，不持有第二套 SSH 会话实现，也不提供 PTY、持续 stdin 或交互式终端。
- 图定义由强类型 Rust DTO 解析并校验。节点、边、条件、状态和事件使用白名单枚举并拒绝未知字段；运行前针对目标服务器再次检查主机信任、系统能力、任务版本和危险确认。
- 自定义命令/脚本文本属于用户明确保存的工作流定义，因此会进入 SQLite 的不可变版本；它不会进入 localStorage、sessionStorage、运行事件、确认弹窗或诊断包。确认弹窗只展示节点名称、操作种类、行数和字符数摘要。
- 工作流事件单调编号并在持久化和发送前脱敏。节点失败保持准确的 `paused`/`uncertain` 状态，后续节点不会继续运行。
- 恢复点只能由登记的上传覆盖节点创建，路径必须位于数据根目录下的 `backups/workflows`。备份记录大小和 SHA-256；回滚校验备份后再上传临时文件并替换，任一步无法确认都会记录 `rollback_failed`。
- 恢复点清理只处理数据库登记的项目内相对路径，并把记录改为 `expired`；运行中的工作流不能清理。
- 诊断包经过服务器凭据 redactor，写入 `downloads` 后只返回相对路径，不包含凭据、私钥、完整敏感参数、脚本文本或本地绝对路径。

## 数据根目录与 C 盘约束

数据根目录解析顺序为：

1. `QINGZHOU_DATA_ROOT` 环境变量；
2. 程序目录存在 `portable.flag` 时的 `data`；
3. 当前用户注册表中保存的路径；
4. 首次启动由用户明确选择。

应用不回退到 `%APPDATA%` 或 `%LOCALAPPDATA%` 保存业务数据。首次选择前的 WebView 使用无痕模式；选择后 WebView2 持久数据固定到 `<数据根目录>\cache\webview2`。

`HKCU\Software\QingzhouSSH\DataRoot` 只保存数据根目录路径指针，不保存业务数据或凭据。当前版本没有图形化数据迁移/重新选择入口：要重新进入便携模式，必须在启动前把 `portable.flag` 放到可执行文件旁；移动目录前应备份，且跨用户/跨电脑移动后 DPAPI 凭据需要重建。

开发工作区通过 `scripts/dev-env.ps1` 和 `scripts/verify-d-drive.ps1` 把可控依赖、缓存、临时文件、测试数据和产物限制在 D 盘项目区域。系统级 WebView2、Windows 注册表、预装 Python/Rust/Node 可执行文件和 Docker Desktop 自身不由仓库控制；若启用 Docker，必须先单独确认其数据根目录。

## 已知范围限制

- 当前没有遥测和自动崩溃上传。
- 当前没有安装包签名、在线更新清单校验、GitHub Releases 或 ModelScope 双源切换；这些能力将在 M4 单独实现和验收。
- 脚本文本按产品定义保存在用户选择的数据根目录，因此数据目录本身应使用合适的 Windows 文件权限并纳入用户备份策略；DPAPI 只保护服务器凭据，不加密全部业务数据库。
- 发现疑似凭据泄漏、主机指纹绕过或路径逃逸时，应停止发布并保留复现步骤，不要提交真实密钥或服务器地址。
