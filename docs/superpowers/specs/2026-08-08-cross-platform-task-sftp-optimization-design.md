# 轻舟 SSH：跨平台快捷任务、脚本与 SFTP 深度优化设计

日期：2026-08-08

状态：用户已批准设计

适用版本：从 v0.1.11 后续版本开始分阶段实施

## 1. 背景与现状

轻舟 SSH 当前使用 Tauri 2、React 19 与 Rust，已经具备快捷任务、个人脚本、高级命令、工作流、执行历史、日志检索和双栏 SFTP。现有安全边界是正确的：内置命令只存在于 Rust 后端，用户参数经过强类型校验，个人脚本按高风险操作处理，所有执行共用主机指纹校验、超时、取消、历史和脱敏能力。

本次优化不重写这些安全基础，而是解决以下结构性问题：

- 客户端目前依赖 Windows DPAPI、注册表、NSIS、Windows 专属更新产物和界面文案，macOS、Linux 与 ARM64 尚未形成可编译、可安装、可验收的交付链路。
- 远端任务以 Linux 为中心，系统能力模型还不能完整表达 BSD 和 Windows Server 的 Shell、服务、进程、网络、日志及路径差异。
- 快捷任务、个人脚本和高级命令在界面上仍像三个相邻工具，缺少统一的目标选择、兼容性说明、运行反馈、最近使用与结果解释。
- 个人脚本编辑体验只有基础文本输入，缺少 Shell 类型、语法辅助、版本对比、离开保护和清晰的运行环境说明。
- 每次远端目录读取、上传或下载都会重新建立 SSH 连接并重复系统能力探测。目录连续导航时，连接和探测成本远大于读取目录本身。
- SFTP 使用固定 64 KiB 缓冲区串行读写。下载前先通过 SFTP 完整读取远端文件计算 SHA-256，随后再完整下载一次；高延迟或大文件场景接近双倍网络流量。
- 前端速度只显示从开始时间计算的总平均值，没有平滑瞬时速度、剩余时间、队列、重试、批量和断点续传。

2026-08-08 基线验证中，前端 26 个测试文件、109 项测试通过，耗时约 51 秒。Rust 全量测试在 5 分钟内没有结束；实施前必须把 Rust 验证拆成可观察的快速集、集成集和真实 SSH/SFTP 集，不能用一次不透明的超长运行作为唯一门槛。

## 2. 目标与成功标准

### 2.1 产品目标

1. 把快捷任务、命令、脚本和工作流统一为一套可理解、可预览、可取消、可追踪的执行体验。
2. 让内置任务根据远端能力选择 Linux/POSIX、BSD 或 Windows PowerShell 的固定实现，不让前端提交任意命令模板。
3. 让个人脚本明确声明 Shell 和兼容范围，并获得适合日常使用的编辑、版本与运行体验。
4. 让客户端核心在 Windows、macOS 和 Linux 上具备等价的凭据保护、数据目录、窗口、更新与安装边界，并覆盖 x64 与 ARM64。
5. 让 SFTP 浏览接近本地文件管理器的响应体验，并显著降低连接、探测和重复校验带来的等待。
6. 让大文件、多文件和高延迟链路具备可测量的吞吐提升，同时保留临时文件、完整性校验、取消和不确定状态等安全语义。

### 2.2 “适配所有系统”的范围定义

“所有系统”在本项目中定义为可持续测试和发布的系统族，而不是声称兼容任何未知系统版本：

- 客户端：Windows 10/11、macOS 当前与前一主版本、Ubuntu LTS；发布 Windows/macOS/Linux 的 x86_64 与 ARM64 产物。其他现代 Linux 发行版通过 AppImage 提供尽力兼容。
- 远端 Linux：Debian/Ubuntu、RHEL/Rocky/AlmaLinux/Anolis、openEuler/Kylin/UOS、Alpine、Arch、openSUSE/SLES。
- 远端 BSD：FreeBSD、OpenBSD。
- 远端 Windows：启用 OpenSSH Server 和 PowerShell 5.1 或 PowerShell 7 的受支持 Windows Server。
- 未识别远端：允许建立 SSH/SFTP 连接；只有能力探测明确证明可用的任务才开放。

每个平台只有在编译、安装、凭据读写、数据目录、SSH、任务、SFTP 和更新/升级矩阵都有证据时才标记为“支持”。仅能编译或仅在预览模式工作不得标记为支持。

### 2.3 性能成功标准

性能以仓库内可重复的 0 ms、40 ms 和 80 ms RTT SSH 夹具测量，并同时记录基线值：

- 同一服务器的第二次远端目录导航不再重新认证或重新探测；80 ms RTT 下目录实际刷新中位耗时相对 v0.1.11 至少降低 50%。
- 已缓存目录在用户返回时立即渲染，后台刷新不清空现有条目；缓存命中到首帧不超过 150 ms。
- 256 MiB 单文件在 80 ms RTT、100 Mbit/s 限速夹具下，默认模式吞吐至少达到可用带宽的 70%，且不低于 v0.1.11 的两倍；达不到时必须保留基准报告并继续调优，不能降低门槛。
- 远端支持哈希命令或 SFTP 哈希扩展时，下载不得再通过网络预读整个文件；校验额外网络流量应接近零。
- 进度事件最多每 100 ms 一次且结束事件不被节流；持续传输时界面每秒更新 5 至 10 次。
- 用户取消后 1 秒内显示“正在取消”，2 秒内关闭对应 SFTP 文件句柄或通道；服务器不可达时进入明确的“不确定/等待重连”状态。
- 单传输的流水线缓冲上限为 16 MiB，全局并发缓冲必须有配置上限，不随文件大小增长。

## 3. 非目标与边界

- 不提供交互式终端、PTY、持续 stdin、全屏 TUI 或自动回答 sudo 密码。
- 不把任意第三方脚本伪装成安全内置任务，不建立在线脚本市场。
- 不为追求速度关闭 SSH 传输层完整性、主机指纹校验或凭据保护。
- 不在没有验证证据时宣称支持所有历史系统版本、所有 SSH/SFTP 服务端或所有桌面环境。
- 不在第一阶段实现跨服务器目录同步、冲突合并或云盘式后台常驻同步。
- 不遥测用户命令、脚本、服务器地址、文件路径或传输内容。性能数据默认只保存在本地诊断结果中，由用户主动导出。

## 4. 总体架构

采用分层渐进式重构，保留现有领域模型和数据库，通过清晰接口替换平台与传输实现：

```text
任务中心 / 脚本中心 / 高级命令 / 工作流 / SFTP UI
                         |
                         v
      统一执行门面 / 传输队列 / 用户可见状态模型
                         |
             +-----------+-----------+
             |                       |
             v                       v
     任务与脚本执行内核         SFTP 传输引擎
             |                       |
             +-----------+-----------+
                         v
           ServerSessionManager（会话、能力、保活）
                         |
             RemotePlatformAdapter
       POSIX/Linux | BSD | Windows PowerShell
                         |
                         v
             经过主机指纹校验的 SSH

客户端平台能力：SecretStore | DataRootStore | Updater | PlatformInfo
```

核心原则：

- 一个执行内核：任务、命令、个人脚本和工作流不各自实现 SSH、取消、脱敏或历史。
- 一个会话管理器：命令和 SFTP 可共享认证与能力缓存，但每次执行使用独立 SSH channel，避免 stdout、取消或失败互相污染。
- 平台实现可替换：领域服务依赖接口，不直接引用 DPAPI、注册表或特定安装器。
- 能力驱动：远端系统名参与分类，真正的可执行性取决于 Shell、命令、服务管理器、路径语义和权限探测。
- 逐阶段可交付：每个子项目完成后都能单独发布、回滚和验证。

## 5. 客户端平台服务

### 5.1 平台接口

Rust 后端新增四个窄接口：

```rust
trait SecretStore {
    fn put(&self, id: &str, secret: &[u8]) -> AppResult<()>;
    fn get(&self, id: &str) -> AppResult<Zeroizing<Vec<u8>>>;
    fn delete(&self, id: &str) -> AppResult<()>;
}

trait DataRootStore {
    fn load(&self) -> AppResult<Option<PathBuf>>;
    fn save(&self, path: &Path) -> AppResult<()>;
    fn clear(&self) -> AppResult<()>;
}

trait PlatformUpdater {
    fn platform_key(&self) -> PlatformKey;
    fn supports_self_update(&self) -> bool;
}

trait PlatformInfo {
    fn client_os(&self) -> ClientOs;
    fn architecture(&self) -> ClientArchitecture;
}
```

接口只表达业务需要，不能把注册表键、Keychain service 名或 Linux 桌面实现泄漏给调用者。

### 5.2 平台实现

- Windows 使用当前用户 DPAPI 和 HKCU 数据目录指针；保留 NSIS 当前用户安装及便携模式。
- macOS 使用 Keychain 保存凭据，数据目录指针保存在用户 Application Support 下；发布签名和公证后的 DMG/应用包。
- Linux 优先使用 Secret Service。Secret Service 不可用时，用户必须设置主密码，以内存派生密钥解锁本地加密凭据库；不得降级为明文。数据目录指针进入 XDG config 目录。
- 无论平台，便携模式都只在显式便携标记存在时启用；平台默认数据目录不会绕过用户已选择的数据根。

现有 `SecretProtector` 可作为 `SecretStore` 过渡适配器，但最终凭据仓库只依赖统一接口。测试使用内存实现，不访问真实用户 Keychain、注册表或 Secret Service。

### 5.3 打包与更新

更新清单从单一 `windows-x86_64` 记录升级为按 `os-architecture-package` 索引的产物集合。客户端只能选择与当前平台完全匹配的签名产物。每个平台继续校验 Tauri 更新签名、SHA-256 和大小。

发布矩阵包括：

- Windows x86_64/ARM64：NSIS 与便携包。
- macOS x86_64/ARM64：DMG；可同时提供 universal 包，但更新清单仍记录实际架构。
- Linux x86_64/ARM64：AppImage；Deb/RPM 为平台包补充，不替代 AppImage 验收。

## 6. 远端平台与能力模型

### 6.1 远端平台描述

`SystemCapabilities` 扩展为显式平台描述：

```rust
struct RemotePlatform {
    family: RemoteOsFamily,
    distribution: String,
    version: String,
    architecture: String,
    shell: RemoteShell,
    path_style: RemotePathStyle,
    service_manager: Option<ServiceManager>,
    package_manager: Option<PackageManager>,
    commands: BTreeSet<String>,
    features: BTreeSet<RemoteFeature>,
}
```

`RemoteOsFamily` 至少包含 `Linux`、`Bsd`、`Windows` 和 `Unknown`；`RemoteShell` 至少包含 `PosixSh`、`Bash`、`PowerShell` 与 `Unknown`。任务实现通过谓词声明所需平台、Shell、命令、服务管理器、权限和特性。

### 6.2 探测策略

- POSIX 首先读取 `uname` 与系统发布文件，再探测固定白名单命令。
- BSD 使用 `uname`、`sysctl`、`service`、`rcctl`、`pkg_info` 等系统专属能力，不复用 Linux 包管理器假设。
- Windows Server 使用非交互 PowerShell 输出带版本的 JSON 探测结果；拒绝依赖本地化的人类可读文本。
- 探测结果带 schema 版本、时间戳和服务器配置修订号，进入会话管理器缓存。
- 服务器地址、端口、用户名、凭据或主机密钥改变时立即失效；普通缓存最长保留 10 分钟，用户可主动刷新。

### 6.3 路径与引用

远端路径不再全局等同于 POSIX 绝对路径：

- POSIX/BSD 继续接受以 `/` 开头且不包含 NUL 或上级逃逸的路径。
- Windows SFTP 路径通过服务端规范化结果建立独立类型，不直接把 PowerShell 路径拼入 SFTP 路径。
- 命令参数分别使用 POSIX shell 引用和 PowerShell 参数/环境变量绑定，不能共享字符串转义函数。
- 用户参数必须先通过语义类型验证，再由目标适配器渲染；前端永远不能提交渲染后的可信任务命令。

## 7. 快捷任务、命令与脚本

### 7.1 统一执行门面

前端通过统一的 `ExecutionIntent` 表达用户意图：

```ts
type ExecutionIntent =
  | { kind: 'builtInTask'; taskId: string; version: number }
  | { kind: 'personalScript'; scriptId: string; versionId: string }
  | { kind: 'advancedCommand'; shell: RemoteShell }
  | { kind: 'workflow'; workflowId: string; version: number };
```

门面统一加载目标服务器、兼容状态、参数表单、风险说明和运行历史。后端仍使用不同的强类型请求，`ExecutionIntent` 不是允许前端提交任意任务实现的通用 IPC。

### 7.2 任务中心信息架构

任务中心保留“快捷任务”导航名称，页面结构调整为：

1. 顶部服务器与批量目标选择。
2. 推荐、最近使用、收藏和系统分类。
3. 搜索与兼容性筛选。
4. 任务列表。
5. 任务详情、参数、影响和运行入口。
6. 运行抽屉与历史入口。

任务卡显示用途、风险、预计耗时和当前系统状态。不可用任务默认隐藏，但筛选器可显示并解释缺少的命令、权限或 Shell。危险任务不能通过右键菜单绕过预演和确认。

### 7.3 参数与预览

- 参数表单根据探测到的服务、网络接口、容器、磁盘和路径提供建议值。
- 自动发现值与用户输入值分开标识；刷新探测不会静默覆盖已编辑参数。
- 预览先显示中文目标、影响、备份/回滚能力、预计耗时和参数摘要。
- 技术详情显示目标适配器、实现 ID、Shell 与固定命令摘要；敏感值和个人脚本正文永不进入摘要。

### 7.4 高级命令

高级命令仍是高风险、一次性、非交互执行。新增：

- 根据远端平台提供 Shell 选择，只显示实际可用 Shell。
- 显示超时、最大输出和取消语义。
- 提供从最近执行复制到编辑器，但复制前明确说明历史中只保存经过产品允许的文本范围。
- 对需要 PTY、持续输入或交互式 sudo 的明显模式给出阻断或警告。
- 运行前显示服务器、Shell、行数、字符数和风险，不在确认弹窗重复完整敏感文本。

### 7.5 个人脚本

个人脚本版本增加 `shell` 和 `compatibility`：

- `posix_sh`、`bash`、`powershell` 是首批支持类型。
- Shell 类型在一个不可变版本中固定；改变 Shell 会创建新版本。
- 参数仍映射为固定 `QZ_PARAM_*` 环境变量；PowerShell 通过进程环境读取，不进行源码字符串替换。
- 导入包带格式版本、Shell、兼容声明、参数定义和内容摘要；导入后继续默认禁用。

编辑器采用按需加载的轻量代码编辑器，提供语法高亮、行号、查找替换、括号匹配、参数名提示、静态风险提示和可访问的纯文本回退。脚本正文只在打开编辑器时从后端读取，不进入 localStorage、sessionStorage、普通事件、诊断包或确认弹窗。

离开有未保存修改的脚本时必须确认。保存总是创建不可变版本；版本视图可比较元数据、参数、Shell 和正文差异。静态扫描只解释风险，不能把个人脚本降级为安全任务。

### 7.6 结果体验

运行结果按以下顺序呈现：

1. 成功、失败、取消或不确定状态。
2. 中文结论和关键指标。
3. 可执行建议，例如刷新能力、检查权限、重试或打开历史。
4. 步骤时间线和结构化结果。
5. 折叠的原始 stdout/stderr 与技术错误。

输出事件在前端有界保存，超出上限的完整输出继续写入数据根文件；界面明确说明已截断并提供受控打开或导出入口。

## 8. SSH 会话管理器

### 8.1 生命周期

新增 `ServerSessionManager`，按服务器 ID 管理经过认证的 SSH transport：

- 首次请求完成主机指纹校验、认证和能力探测。
- 后续目录读取、任务和传输复用 transport，但各自打开独立 channel。
- 每台服务器默认最多 4 个活动 channel，其中传输并发默认 2；全局传输并发默认 3。
- transport 空闲 90 秒后关闭；应用休眠、网络变化、认证错误或协议错误会使 transport 失效。
- 复用前执行廉价活性检查；首次通道失败时允许在确认主机指纹仍匹配后透明重连一次。
- 主机密钥、地址、端口、用户名或凭据更新会立即关闭旧 transport 并清除能力与目录缓存。

会话管理器不长期保存明文凭据。连接过程从 `SecretStore` 取得 `Zeroizing` 数据，认证完成后释放。transport 只持有协议会话需要的状态。

### 8.2 并发与取消

每次工作获得 `SessionLease` 和独立 channel。取消一个任务只关闭该 channel，不主动断开同服务器的其他安全工作；transport 已失效或服务器无响应时才整体断开并通知所有租约。

等待并发槽位的请求可以取消，并在 UI 中显示“排队中”。危险修改任务继续保持单服务器、单修改执行约束，不因会话池而并行。

## 9. SFTP 浏览体验

### 9.1 目录状态模型

目录缓存从全局内存 Map 升级为每服务器会话缓存条目：

```ts
interface DirectoryCacheEntry {
  listing: DirectoryListing;
  fetchedAt: number;
  generation: number;
  state: 'fresh' | 'stale' | 'refreshing';
}
```

- 返回已访问目录时立即展示缓存，再后台刷新。
- 相同服务器和路径的并发请求去重。
- 每个面板维护递增 generation；旧请求即使晚返回也不能覆盖新路径。
- 切换服务器、修改服务器配置或完成相关文件操作时精确失效对应缓存。
- 目录结果在 5 秒内视为 fresh；超过 5 秒仍可立即展示，但必须进入 refreshing 并后台刷新。SSH transport 关闭时清除该服务器的陈旧目录结果。
- 默认最多缓存 128 个目录，并使用 LRU 淘汰；缓存只包含目录元数据，不持久化到浏览器存储。

### 9.2 文件管理交互

双栏布局保留，并增加：

- 可点击面包屑和可编辑路径输入框。
- 前进、后退、上级、刷新与回到最近目录。
- 名称、大小、修改时间和类型排序。
- 键盘上下移动、Enter 打开、Backspace 返回、输入前缀定位。
- 隐藏文件开关、多选、全选和清晰的选择计数。
- 从系统文件管理器拖放到远端面板创建上传队列。
- 上传、下载、新建目录、重命名和删除使用对象相关右键菜单；覆盖、删除和批量危险操作必须预览并确认。
- 下载目标是左侧当前本地目录，首次打开仍默认使用 `<data-root>/downloads`。用户通过系统目录选择器明确授权其他绝对目录；后端规范化并校验目标，不接受前端拼接出的相对路径。

超过服务端/客户端目录上限时不伪装成完整目录。界面显示“仅展示前 N 项”并提供当前结果过滤。标准 SFTP `read_dir` 没有可靠的跨服务端分页合同，因此本期不宣称支持超大目录分页。

### 9.3 无障碍与小窗口

所有图标按钮有可见提示和可访问名称。窄窗口切换为单栏分页视图，保留本地/远端选择和传输队列，不把双栏强行压缩到不可用宽度。焦点在对话框、右键菜单和传输完成后有明确返回位置。

## 10. SFTP 传输引擎

### 10.1 队列模型

单次表单状态升级为由后端管理的传输队列。作业定义、状态和恢复元数据写入数据根数据库，使应用重启后能够解释并恢复未完成作业；文件内容和明文凭据不进入数据库：

```rust
struct TransferJob {
    id: Uuid,
    server_id: String,
    direction: TransferDirection,
    source: TransferEndpoint,
    destination: TransferEndpoint,
    overwrite: OverwritePolicy,
    verification: VerificationPolicy,
}
```

队列项状态包含 `queued`、`connecting`、`transferring`、`verifying`、`finalizing`、`paused`、`succeeded`、`failed`、`cancelled` 和 `uncertain`。状态、字节、速度、ETA、重试次数和错误均按项展示。应用退出时，能够安全续传的作业转为 `paused`；已经进入远端收尾但无法确认结果的作业恢复为 `uncertain`，不能简单标记失败。

目录传输先生成有界清单，再逐文件入队。符号链接默认跳过并提示，不自动跟随到目录树外。单个失败不取消其他文件；用户可取消整个批次。

### 10.2 流水线与分块

- 建立 SFTP 会话后读取服务端 limits/扩展；不存在协商信息时使用经过夹具验证的保守值。
- 分块从 256 KiB 起步，根据 RTT、吞吐和服务端限制在 64 KiB 至 2 MiB 范围内调整。
- 同一文件保持有界的读写流水线窗口，默认最多 8 个在途请求且总缓冲不超过 16 MiB。
- 本地文件读写使用异步缓冲；哈希随数据流计算，不额外读取本地文件。
- 进度按时间或显著字节变化合并，最多 10 Hz；最后一条进度和终态始终立即发送。

具体流水线实现必须以 `russh-sftp` 当前版本实际提供的 offset read/write 和 request 并发语义为准。若库不能安全支持所需窗口，先升级到经过锁定与集成测试的版本，或在协议层实现有界调度；不得通过无界 `spawn` 模拟流水线。

### 10.3 速度与 ETA

后端事件增加时间窗口采样，前端使用 EWMA 展示平滑速度：

- 瞬时速度：最近窗口的指数平滑值。
- 平均速度：总字节除以实际传输阶段耗时，不包含排队和连接。
- ETA：剩余字节除以平滑速度；样本不足或速度接近零时显示“计算中”。
- 阶段耗时分别记录连接、传输、校验和收尾，便于诊断。

### 10.4 临时文件、覆盖与原子完成

- 上传继续写入同目录的唯一 `.qingzhou-*.partial`，成功校验后重命名。
- 下载继续写入目标旁的 `.partial`，刷新并同步后再替换目标。
- 覆盖优先使用服务端原子 rename/posix-rename 扩展。服务端不支持时，预览必须说明存在短暂替换窗口；失败后保留原目标或进入明确不确定状态。
- 清理只针对当前作业创建并验证所有权的临时文件，不能按通配符删除其他文件。

### 10.5 断点续传

暂停或中断时，临时文件旁保存不含凭据的恢复元数据：源标识、源大小、修改时间、目标、已完成偏移、前缀哈希和作业版本。

恢复前重新检查：

- 服务器身份和目标路径未变化。
- 源大小与修改时间未变化。
- 临时文件长度等于记录偏移。
- 已传前缀抽样或哈希一致。
- 服务端支持 offset 读写且目标仍是当前作业的临时文件。

任一条件不满足就拒绝续传并提供安全重传。暂停只在上述条件可成立时开放；否则界面提供取消，不伪装成可恢复暂停。

### 10.6 完整性校验

校验策略包含：

- `balanced`（默认）：SSH 传输层完整性、大小检查、流内本地 SHA-256；优先通过 SFTP `check-file` 扩展或远端固定哈希命令取得另一端哈希并比较。
- `strict`：必须取得两端 SHA-256；若服务端没有扩展或哈希命令，允许通过 SFTP 二次读取远端文件，但在开始前明确说明额外时间与流量。
- `transport_only`：只用于用户明确选择的低风险、可重新获取文件；仍计算接收端本地 SHA-256 并标记“未与远端哈希比较”。

远端固定哈希实现按能力选择 `sha256sum`、`shasum -a 256`、BSD 对应工具或 PowerShell/.NET 流式哈希。动态路径使用平台专属安全参数绑定。默认下载不再先通过 SFTP 完整预读远端文件。

### 10.7 重试与不确定状态

- 连接建立前失败可安全重试。
- 传输中断且续传条件满足时，从已验证偏移恢复。
- 完成重命名后连接中断时，远端结果可能已生效，状态必须是 `uncertain`；重新连接并检查大小、临时文件和目标哈希后才能转换为成功或失败。
- 自动重试默认最多 2 次并使用带抖动退避；认证、主机密钥、权限、空间不足和完整性错误不自动重试。

## 11. 错误模型与用户文案

错误 DTO 统一包含：

```rust
struct UserFacingError {
    code: String,
    summary: String,
    detail: String,
    retryable: bool,
    state_uncertain: bool,
    suggested_actions: Vec<SuggestedAction>,
}
```

界面优先回答四件事：发生了什么、是否影响远端/本地状态、能否重试、下一步做什么。技术详情保留底层错误链和阶段，但必须经过凭据与路径边界脱敏。

常见错误分别处理：主机密钥变化、认证失败、Shell 不兼容、缺少命令、权限不足、路径无效、文件已存在、空间不足、网络中断、校验失败、取消和状态不确定。缓存内容可以在刷新失败时继续展示，但必须标记为旧数据。

## 12. 数据与兼容迁移

- 数据库迁移只新增字段和表，不破坏旧执行历史。
- 旧个人脚本迁移为 `posix_sh`，因为当前执行语义固定为非交互 `sh`；迁移后创建带来源说明的新版本，不重写旧正文。
- 旧传输历史继续可读；新阶段、验证策略和恢复元数据使用可选字段或独立表。
- 新传输队列只保存作业意图、公开状态和恢复校验数据；用户选择的数据根之外的本地绝对路径按现有历史隐私规则裁剪，不写入普通诊断报告。
- 能力缓存和目录缓存属于可丢弃数据，不进入长期备份合同。
- 跨平台凭据不尝试直接解密迁移。用户把数据根复制到另一操作系统后，业务数据可读取，但服务器凭据必须重新录入。

## 13. 安全约束

- 每次新 SSH transport 都重新执行主机指纹固定检查；会话复用不绕过首次信任或指纹变化阻断。
- 会话池不记录明文凭据，不把会话对象暴露给前端。
- 内置任务实现只存在于可信 Rust 代码；前端只提交稳定 ID、版本和参数。
- POSIX 与 PowerShell 使用不同的参数绑定和路径类型，禁止复用不匹配的转义函数。
- 个人脚本正文不进入浏览器存储、普通事件、确认弹窗、报告或诊断包。
- 传输缓存、恢复元数据和性能结果不包含凭据；远端路径在公开报告中按现有隐私策略裁剪。
- 批量、目录递归、输出、队列、并发、缓冲、重试和恢复元数据都有硬上限。
- 覆盖、删除、重命名、危险任务和个人脚本继续使用明确确认；缓存或右键菜单不能绕过确认。

快速集必须能单独运行并在 CI 中给出每个测试二进制的耗时。当前 Rust 全量测试超过 5 分钟的问题在功能实现前定位并分层。

### 14.2 SSH/SFTP 集成矩阵

夹具覆盖：

- 目录读取、Unicode 文件名、空文件、大文件、覆盖、权限拒绝、空间不足、断网、取消、重连、续传和哈希不一致。

### 14.4 性能基准

仓库增加可重复脚本，控制 RTT、带宽和丢包，输出 JSON 与可读摘要。至少测量：

- 冷连接、热连接、能力探测和目录首屏时间。

- 1 个大文件与 1,000 个小文件。
- balanced/strict 校验开销。
- 并发 1/2/3、CPU、峰值内存、IPC 事件数、取消延迟和重连时间。

性能验收比较同一机器、同一夹具、同一网络参数下的 v0.1.11 基线和当前实现。报告必须保留原始参数，不能只记录“更快”。

## 15. 分阶段实施

本设计拆为五个独立、可测试、可发布的子项目，每个子项目使用单独实施计划：

1. **执行体验与远端 Shell 模型**：统一任务流、Shell/平台能力、脚本版本与编辑体验，为 Windows/BSD 实现建立类型边界。
2. **SSH 会话与 SFTP 性能内核**：会话复用、能力缓存、目录请求竞态修复、流水线、进度节流、校验策略和性能基准。
3. **SFTP 文件管理与队列**：多选、拖放、批量/目录、队列、重试、断点续传、错误恢复和窄窗口体验。
4. **客户端跨平台基础**：SecretStore、DataRootStore、平台文案、Windows/macOS/Linux 编译与凭据验证。
5. **远端与发布矩阵**：BSD、Windows Server 任务实现，x64/ARM64 打包、更新清单和完整验收。

顺序依赖为：子项目 1 和 2 可在边界约定完成后并行；子项目 3 依赖 2；子项目 4 可与 1/2 并行；子项目 5 依赖 1 和 4。任何阶段都不能通过删除现有安全检查或降低测试门槛换取通过。

## 16. 完成标准

- 支持矩阵中的客户端和远端系统均有真实或可复现夹具证据，文档状态与证据一致。
