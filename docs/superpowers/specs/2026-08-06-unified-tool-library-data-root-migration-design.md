# 轻舟 SSH 统一工具库、兼容性修复与数据目录迁移设计

日期：2026-08-06  
状态：已完成用户分段确认，等待书面规格终审

## 1. 背景

当前快捷任务页存在四个直接影响小白用户的问题：

1. 任务可用性只有 `compatible: true/false`，缺少命令、权限不足、系统不支持和实现尚未完成都被压缩成“兼容/不兼容”。
2. 任务卡片一次性铺满页面，参数与运行区位于整个卡片网格之后；点选上方卡片后必须滚动到底部才能继续。
3. 内置任务、个人脚本和高级命令入口分散，缺少面向使用场景的统一分类与搜索。
4. 设置页只展示数据目录。启动后数据库、服务对象、更新器和 WebView2 缓存均绑定当前目录，没有安全的运行时迁移入口。

现有兼容判定还会把所有只读任务限制在 Debian、RHEL 和 openEuler 三个已映射家族内。即使未知发行版已经具备所需命令，也会被拒绝。截图中的典型情况包括：

- UDP 探测只有在远端存在 `nc` 或 `ncat` 时可用。
- 限时抓包要求 `tcpdump`、`timeout` 和 `wc`。
- 修改 IP 需要网络后端、延迟回滚调度器和一组恢复命令；它不是安装单个软件包即可安全启用的任务。
- 前端禁用不兼容卡片，只显示“不兼容”，没有展示缺失项或解决办法。

## 2. 目标与设计原则

本次改造目标：

- 把任务状态拆分为可直接运行、可补齐组件、权限不足和当前系统不支持。
- 对缺少依赖但存在安全实现的任务提供明确、需确认的组件安装流程。
- 把内置任务、个人脚本和受审核命令模板组织为统一工具库。
- 桌面宽度使用固定右侧详情栏；窄窗口使用右侧抽屉，点选后无需滚动页面即可操作。
- 设置页允许随时更改数据目录，复制并校验全部数据后再切换，旧目录始终保留。

设计原则：

1. 能力优先于发行版名称。通用只读任务以实际命令能力为准；只有命令语法、文件位置或恢复机制依赖发行版时才限制系统家族。
2. 不把缺依赖误报为系统不支持，也不把未完成的危险操作伪装成“可安装后运行”。
3. 软件包名称和安装命令只能来自后端白名单，前端不能提交任意包名或命令。
4. 不静默安装、不自动继续执行原任务、不保存或传递 sudo 密码。
5. 数据目录只有在应用退出、文件复制完成且校验全部通过后才能切换。
6. 所有用户可控数据继续避开 C 盘 AppData、磁盘根目录和未经选择的位置。

## 3. 已确认的产品决策

- 缺少组件时显示“可补齐组件”，用户确认后由工具安装所需白名单包。
- 任务详情采用固定右栏；窄窗口改为抽屉。
- 内置任务、个人脚本和命令模板进入同一个工具库和搜索入口。
- 数据目录迁移采用复制、逐项校验、切换并重启；旧目录保留，不自动删除。
- 默认目录只展示“可直接运行”和“可补齐组件”；权限不足和当前系统不支持通过状态筛选查看。
- 本轮仅生成新的本地测试包，不自动发布 GitHub、ModelScope 或在线更新。

## 4. 总体架构

```text
系统能力探测
    |
    v
可用性分析器 ----> 依赖补齐计划 ----> 受控软件包安装 ----> 重新探测
    |
    v
统一工具索引 <---- 内置任务 / 个人脚本 / 受审核命令模板
    |
    v
场景分类 + 搜索 + 状态筛选
    |
    v
固定右侧详情栏 / 窄窗口抽屉
    |
    v
现有任务、操作、脚本与执行历史服务
```

数据目录迁移保持独立：

```text
设置页选择目标
    -> 迁移预检
    -> 等待运行中操作结束
    -> 保存迁移事务
    -> 客户端退出
    -> 无控制台迁移进程复制和校验
    -> 原子切换路径指针
    -> 重启并从新目录打开
```

## 5. 可用性模型

### 5.1 状态

后端用稳定枚举表达任务状态：

```rust
enum AvailabilityState {
    Ready,
    Remediable,
    PermissionBlocked,
    Unsupported,
}
```

对前端返回的可用性信息至少包含：

- 状态。
- 面向用户的中文摘要。
- 缺失命令列表。
- 当前账号所缺权限。
- 可选的依赖补齐计划。
- 仅在技术详情中展示的系统家族、服务管理器和实现候选信息。

现有 `compatible` 布尔值不再作为前端判断依据。迁移期间可以在 IPC 合同中保留只读兼容字段，但新页面、测试和后端执行入口必须使用状态枚举并在后续合同版本中移除旧字段。

### 5.2 能力匹配

- 通用只读实现如果所有必需命令存在，可以在未知系统家族运行。
- 涉及系统配置文件、包管理器、服务管理器或回滚资产的实现仍要求明确系统家族。
- 多实现任务选择满足条件的现有实现，不要求安装所有实现的依赖。
- 如果没有现有实现，分析器计算每个候选实现的最小缺失命令集合，只在存在审核过的软件包映射时返回 `Remediable`。
- 缺少 root 或免密 sudo 时，修改任务返回 `PermissionBlocked`；不尝试交互式 sudo。
- 没有安全实现、缺少无法补齐的内核能力或恢复机制尚未实现时返回 `Unsupported`。

### 5.3 依赖补齐计划

补齐计划由后端生成，包含：

- 目标任务与候选实现。
- 检测到的 `apt`、`dnf` 或 `yum`。
- 白名单软件包名称。
- 将获得的命令能力。
- 权限要求、预计耗时和风险说明。
- 安装后验证命令。

首批映射至少覆盖：

| 能力 | Debian/Ubuntu/麒麟/UOS | RHEL/Rocky/Anolis | openEuler |
|---|---|---|---|
| `nc`/`ncat` | `netcat-openbsd` | `nmap-ncat` | `nmap-ncat` |
| `tcpdump` | `tcpdump` | `tcpdump` | `tcpdump` |
| `lsof` | `lsof` | `lsof` | `lsof` |
| `iostat` | `sysstat` | `sysstat` | `sysstat` |
| `dig` | `dnsutils` | `bind-utils` | `bind-utils` |

映射是编译进客户端的静态白名单。前端只提交补齐计划 ID 和确认标志，不能修改包名。安装使用现有 root 或 `sudo -n` 权限。软件源元数据刷新不与安装静默绑定；如果包索引过期，错误提示可以提供单独、再次确认的刷新操作。

依赖安装本身属于修改类操作，记录执行历史并展示目标、包名和结果。安装成功后只重新探测并刷新目录，不自动运行原任务。卸载软件包不能作为自动回滚，因为它可能影响服务器已有依赖和配置。

### 5.4 现有目录审计

每个任务必须落入以下一种可解释结果：

- 存在可直接运行的实现。
- 存在可通过白名单包补齐的实现。
- 仅受当前账号权限阻止。
- 当前版本没有安全实现，归入暂不支持。

UDP 探测和限时抓包优先成为可补齐任务。修改 IP 必须在远端延迟回滚、独立重连验证和失败恢复闭环全部实现后才能离开 `Unsupported`；不能仅靠安装 `nmcli`、`netplan`、`systemd-run` 或 `at` 解锁。

## 6. 统一工具库

### 6.1 来源

统一索引包含三种来源：

- `built_in_task`：编译进 Rust 后端的可信任务。
- `personal_script`：用户数据目录中的版本化脚本，始终为高风险且不可自动回滚。
- `command_template`：内置审核命令模板，复用可信任务参数和执行路径，不开放任意 Shell 结构。

任意命令与任意脚本编辑仍保留在“高级执行”。统一工具库不会把任意输入伪装成受审核模板。

### 6.2 面向小白的场景分类

主分类使用用户意图：

1. 推荐与最近。
2. 日常巡检。
3. 性能变慢。
4. 磁盘空间。
5. 网络访问。
6. 网站服务。
7. 安全登录。
8. 服务管理。
9. 容器。
10. 系统设置。
11. 我的脚本。

`system`、`storage`、`network` 等技术类别保留为二级标签和执行历史字段，不作为小白的主要导航。

### 6.3 搜索

搜索范围包含名称、说明、场景分类、技术标签、来源和内置中文别名。别名覆盖“网站打不开”“端口被占用”“磁盘满了”“服务器很慢”“登录失败”等常见描述。

搜索完全离线，不上传输入。内置任务和命令模板使用编译时别名；个人脚本使用标题、分类和标签。个人脚本可以声明所需命令，未声明时显示“运行前检查”，不能通过文本扫描误判为安全。

筛选项包括来源、风险、可用状态、收藏和最近使用。默认只选中 `Ready` 与 `Remediable`；`PermissionBlocked` 与 `Unsupported` 可以主动查看。

### 6.4 桌面布局

桌面宽度采用三栏：

- 左栏：场景分类。
- 中栏：搜索、筛选和工具卡片。
- 右栏：固定详情、参数、依赖补齐、运行状态和结果。

点击卡片只替换右栏内容，不改变主滚动位置。运行按钮、补齐组件按钮或主要阻塞原因必须出现在右栏首屏。

工具卡显示：名称、用途、来源、风险和可用状态。`Remediable` 使用琥珀色并写“可补齐组件”，不能继续使用半透明禁用卡片代替解释。

### 6.5 窄窗口布局

- 场景分类改为横向可滚动标签。
- 工具卡改为紧凑单列。
- 详情栏改为可关闭的右侧抽屉。
- 抽屉使用“参数 / 结果”内部页签和局部滚动，不把整个页面向下撑长。
- 运行或安装按钮保持在抽屉首屏或固定底部操作区。

## 7. 依赖安装交互

当选择 `Remediable` 工具时，右栏显示：

- 缺少哪些能力。
- 将安装哪些软件包。
- 当前系统和包管理器。
- 是否具备 root 或免密 sudo。
- “查看并安装组件”按钮。

确认弹窗再次展示目标服务器、包名、安装影响和不会自动运行原任务的说明。安装过程中显示阶段、有限输出和取消语义。安装结束后重新执行系统能力探测：

- 能力满足：状态变为“可直接运行”。
- 软件源不可用：提示检查网络或镜像源。
- 包不存在：提示当前系统仓库不提供该包，并保留技术详情。
- 权限不足：提示使用具备 root/免密 sudo 的服务器账号。
- SSH 中断：结果为失败或状态不确定，不显示安装成功。

## 8. 数据目录随时修改

### 8.1 设置入口

设置页数据目录卡片增加：

- “更改位置”。
- 当前模式：安装版自定义、便携默认、便携自定义或环境变量管理。
- 最近一次迁移状态。
- 成功迁移后的旧目录备份位置。

便携模式可以选择自定义位置，也可以恢复“跟随程序目录”。`QINGZHOU_DATA_ROOT` 仍拥有最高优先级；存在该变量时界面只读并显示“由启动环境管理”。

安装版路径指针保存在当前用户注册表。便携版自定义指针保存在可执行文件旁的受限指针文件；没有自定义指针时继续使用程序旁 `data`。指针只保存路径，不保存凭据或业务数据。

### 8.2 预检

目标目录必须满足：

- 绝对路径且可创建、可写、可同步落盘。
- 不是 `C:\`、`D:\` 等磁盘根目录。
- 不是当前数据目录、当前目录的子目录或父目录。
- 不是符号链接、目录联接或其他会逃逸目标位置的重解析路径。
- 是空目录，或是同一迁移事务留下的未完成目标；不与另一套轻舟数据合并。
- 可用空间不小于源目录总大小加校验和临时文件余量。

预检还检查任务、脚本、传输、工作流、回滚和更新下载状态。存在活动操作时不强制终止，提示用户等待或主动取消。

### 8.3 迁移事务

为避免数据库、WebView2 和日志文件在复制中继续变化，迁移由应用退出后的同一签名可执行文件完成，不打开命令行窗口。

事务状态为：

```text
prepared -> copying -> verifying -> switched -> completed
                        \-> failed
```

迁移步骤：

1. 在旧目录写入有界迁移事务，记录迁移 ID、规范化源路径、目标路径和状态。
2. 停止接受新操作并确认所有活动操作结束。
3. 正常关闭数据库、更新器和 WebView 后退出主客户端。
4. 迁移进程复制 `app.db`、`vault`、`logs`、`downloads`、`backups`、`templates`、`cache`、`updates` 和其他已声明业务目录。
5. 对每个普通文件按相对路径、字节数和 SHA-256 校验；目录和空目录单独登记。
6. 全部校验通过后，在目标目录写入完成标记和迁移报告。
7. 原子更新安装版注册表指针或便携版指针文件。
8. 从新目录重启主客户端并读取迁移报告。

旧目录不删除、不清空、不改名。设置页显示其位置并允许“打开旧目录”，但本期不提供自动删除按钮。

### 8.4 失败与恢复

- 复制或校验失败时不修改活动路径指针。
- 客户端从旧目录重新启动并显示中文失败原因。
- 目标目录保留未完成标记，可从设置页重试同一事务或由用户手动删除。
- 如果迁移进程在切换前崩溃，启动器继续使用旧目录。
- 如果路径指针已经切换但目标缺少完成标记，启动器拒绝打开不完整目标并回退旧目录事务记录。
- 同一 Windows 用户和电脑内迁移不会改变 DPAPI 安全上下文；跨用户或跨电脑复制仍要求重新录入凭据。

## 9. 安全边界

- 软件包补齐只接受后端生成的短期计划 ID，计划绑定服务器、任务、实现、包管理器和包集合。
- 包名、安装模板、验证命令和允许的软件源操作均编译进可信后端。
- 不接受前端任意包名、仓库地址、Shell 片段或 sudo 密码。
- 个人脚本仍执行静态检查、参数环境变量隔离、二次确认和脱敏；统一搜索不会改变其风险级别。
- 数据迁移路径在 Rust 层规范化和验证，所有目标写入均限制在新根目录内。
- 迁移报告不得包含密码、私钥、令牌、脚本文本或任意凭据明文。
- 迁移和依赖安装都写入本地审计记录；主界面展示中文结论，原始输出只进入受限技术详情。

## 10. 错误处理

错误主提示回答“发生了什么、为什么、下一步怎么做”，并区分：

- 缺少可安装组件。
- 系统仓库没有对应包。
- 软件源或网络不可用。
- 当前账号权限不足。
- 系统或危险恢复机制不支持。
- 数据目标不可写或空间不足。
- 目标目录冲突或路径不安全。
- 数据复制、哈希校验或路径切换失败。
- 迁移或远端操作状态不确定。

主界面不得出现 `[object Object]`、Rust 调试文本或未经解释的 Shell stderr。

## 11. 测试设计

### 11.1 Rust 单元测试

- `Ready`、`Remediable`、`PermissionBlocked` 和 `Unsupported` 的状态决策。
- 未知发行版具备通用只读命令时可以运行。
- 危险任务不会因仅安装命令而绕过恢复机制要求。
- 多实现任务选择已有能力或最小可补齐集合。
- apt、dnf、yum 白名单软件包映射和未知包拒绝。
- 补齐计划绑定、过期、篡改、重复使用和权限拒绝。
- 数据根路径规范化、磁盘根目录、父子目录、重解析点和已有目标拒绝。
- 迁移事务状态转换、逐文件哈希、切换前失败和切换后恢复。

### 11.2 系统能力夹具

覆盖 Debian、Ubuntu、RHEL、Rocky、openEuler、银河麒麟、UOS 和 Anolis，包括：

- 已安装全部依赖。
- 缺少 `nc/ncat`、`tcpdump`、`lsof`、`iostat` 或 `dig`。
- root、免密 sudo 和无提升权限账号。
- 未知发行版但具备通用 POSIX/只读命令。
- 软件源失败、包不存在和安装后探测仍失败。

### 11.3 前端测试

- 统一来源、场景分类、中文别名搜索、状态和来源筛选。
- 默认只显示可直接运行与可补齐组件。
- 选择任意卡片后右侧详情首屏可见，不改变主目录滚动位置。
- `Remediable` 显示安装入口，`PermissionBlocked` 与 `Unsupported` 显示正确说明且不能运行。
- 软件包确认、安装进度、成功后刷新和失败中文提示。
- 数据目录预检、迁移确认、重启提示、失败和旧目录展示。

### 11.4 响应式与端到端测试

- 1920×1080、1366×768、1180×760 和 960×640。
- 宽屏固定右栏，窄屏右侧抽屉；无全局横向滚动。
- 从缺少依赖到确认安装、重新探测和任务可运行的完整 fixture 流程。
- 数据目录成功迁移、空间不足、文件锁、复制中断、校验失败和启动回退。
- 现有服务器、日志、SFTP、工作流、历史、更新和个人脚本回归。
- 路径审计确认应用可控数据未写入 C 盘 AppData、磁盘根目录或项目外测试目录。

## 12. 非目标

- 不部署常驻远端代理。
- 不开放任意软件包、仓库或安装命令。
- 不支持交互式 sudo 密码输入。
- 不自动删除旧数据目录。
- 不把不安全或尚未完成的危险任务强行标为兼容。
- 不在本轮自动发布在线更新。

## 13. 完成标准

- 现有任务目录全部具有可解释状态，不再出现只有“不兼容”而无原因的卡片。
- 可安全补齐的缺失组件能够按系统生成白名单计划，经用户确认安装并重新探测。
- 默认目录不展示真正不支持的任务；用户可以通过筛选查看原因。
- 内置任务、个人脚本和命令模板可在一个入口按场景、关键词、来源、风险和状态查找。
- 点选任意工具后无需滚动到底部即可看到主要操作。
- 数据目录可以从设置页修改；校验成功后切换并重启，旧目录完整保留。
- 所有新增测试和既有回归门禁通过，生成新的本地测试包后停止，等待用户验证。
