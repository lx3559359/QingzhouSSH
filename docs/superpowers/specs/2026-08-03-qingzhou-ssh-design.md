# 轻舟 SSH（QingzhouSSH）设计规格

- 状态：已批准，正在按四个里程碑实施
- 日期：2026-08-03
- 客户端：Windows 桌面应用
- 许可：Apache-2.0
- 技术路线：Tauri 2 + React + TypeScript + Rust + SQLite

## 1. 产品目标

轻舟 SSH 是一款公开下载、纯本地运行的 Windows 桌面工具。它通过 SSH 和 SFTP 连接远程 Linux 主机，将常见操作包装成可理解的任务卡片、参数表单和可视化工作流，使几乎不懂 Linux 的用户也能完成系统检查、服务管理、日志检索和文件下载。

产品不提供传统交互式终端。普通模式隐藏原始命令，高级模式允许用户编辑单条命令、多行 Shell 脚本和工作流，但输出仍进入结构化结果与日志界面。

首版成功标准：

- 新用户能自行添加一台 Linux 服务器并完成连接测试。
- 客户端能自动识别系统族、包管理器、服务管理器和 CPU 架构。
- 用户无需输入 Linux 命令即可完成系统状态、服务管理和日志检索下载。
- 工作流支持线性步骤和条件分支，失败时可暂停、重试失败节点或按恢复点回滚。
- 凭据不以明文落盘，不进入日志，不上传云端。
- 更新包未通过签名与哈希校验时绝不安装。
- 在参考 Windows 11 设备上，冷启动目标不超过 3 秒，空闲工作集目标不超过 150 MB；安装包目标不超过 35 MB，不含可选的固定版 WebView2 运行时。

## 2. 用户与使用边界

主要用户是拥有服务器地址和登录凭据、但几乎不懂 Linux 命令的个人用户。用户自行维护服务器、凭据、快捷任务和工作流，不存在管理员、团队权限或中央控制端。

高级用户可以进入高级模式创建自定义命令与脚本。高级模式必须明确提示风险，且不能改变凭据保护、主机指纹验证、日志脱敏和更新签名等安全规则。

## 3. 首版范围

### 3.1 服务器与认证

- 单次操作或工作流只针对一台服务器。
- 认证支持用户名加密码、用户名加私钥；私钥口令可选。
- 首次连接展示服务器主机密钥指纹并由用户确认。
- 已保存主机的指纹发生变化时阻止连接，展示旧指纹、新指纹和处理说明，不允许静默接受。
- 支持连接测试、超时、取消和可理解的错误分类。

### 3.2 Linux 自动识别

连接后读取 `/etc/os-release` 的 `ID`、`ID_LIKE` 和版本，同时探测：

- `apt`、`dnf`、`yum` 等包管理器；
- `systemd` 或传统 `service`；
- CPU 架构、默认 Shell 和任务需要的命令；
- 当前用户权限及任务是否需要提权。

首版适配 Ubuntu、Debian、Rocky Linux、AlmaLinux、统信 UOS、银河麒麟、openEuler 和龙蜥 Anolis OS。模板按“系统族 + 能力条件”选择实现，不按产品名称硬编码整套逻辑。无法确认兼容性时，任务默认不可执行，并解释缺失能力。

### 3.3 内置快捷任务

首批内置任务分为三类：

1. 系统状态：CPU、内存、磁盘、网络、进程和基础系统信息。
2. 服务管理：查看、启动、停止和重启服务。
3. 日志检索与下载：在预设路径基础上允许临时修改，支持关键词、时间范围、大小写、上下文行数和结果上限。

日志任务支持普通文本日志和常见 `.gz` 压缩日志。结果采用流式读取、分页预览和本地文件下载，不能把无限输出一次性加载进内存。下载文件写入用户选择的数据目录。

### 3.4 自定义命令与脚本

- 高级模式支持单条命令、参数化命令和多行 Shell 脚本。
- 高级编辑器不是交互式终端；每次执行都有固定输入、输出、退出码和超时。
- 普通模板的路径、服务名、关键词、数字和枚举参数按类型校验与转义，不能直接拼接未经处理的输入。
- 自定义脚本允许更高自由度，但执行前展示脚本摘要、目标服务器和风险提示。

### 3.5 文件传输

- 支持简单上传和下载，以及在任务或工作流中引用本地文件。
- 上传和下载使用 SFTP 流式传输并校验 SHA-256。
- 首版不提供完整双栏文件管理器、目录同步或批量文件队列。

### 3.6 可视化工作流

首版节点类型：开始、执行快捷任务、执行自定义脚本、上传文件、下载文件、检索日志、条件判断、停止并提示。

工作流支持线性连接和条件分支。条件只能基于退出码、结构化结果字段或受限的输出匹配。首版不支持循环、并行、多服务器批量运行或人工审批节点。

画布左侧是步骤库，中间是节点和连线，右侧是所选节点的表单参数。原始命令折叠在高级设置中。工作流运行前执行完整校验，包括断开的节点、不可达分支、缺失参数、系统不兼容和危险操作。

### 3.7 执行、取消和恢复

每个任务和节点记录等待、运行、成功、失败、取消、跳过状态，以及开始时间、耗时、退出码和结构化结果。

失败默认暂停工作流，不自动执行可能扩大影响的后续节点。用户可：

- 仅重试失败节点；
- 查看恢复建议；
- 执行已定义的回滚步骤；
- 停止并保留现场；
- 下载脱敏诊断包。

覆盖文件或部署前创建恢复点。恢复点必须包含恢复所需的文件、元数据和适用条件。回滚前再次展示影响。

关闭 SSH 通道不等于远程进程已停止。支持取消的脚本通过受控进程组启动，先请求正常终止，再按策略强制终止；无法确认远程进程状态时必须警告用户，不能显示“已取消成功”。

## 4. 交互与视觉设计

### 4.1 信息架构

主导航包括：首页、服务器、快捷任务、工作流、执行记录、下载文件和设置。

首页先展示服务器，再展示系统状态、服务管理和日志检索等常用任务。用户核心路径是：添加服务器与凭据 → 自动识别系统 → 选择任务或工作流 → 填写表单 → 确认影响 → 查看结构化结果。

### 4.2 视觉基线

- 卡片使用统一白银渐变、清晰边缘高光和三层阴影，避免完全扁平化。
- 卡片内部高光必须裁剪在圆角边界内；外部立体感仅使用盒阴影，避免伪元素溢出。
- 彩色主要用于图标、状态和主操作按钮；正文保持高对比度深色文字。
- 主操作使用蓝紫渐变，成功使用绿色，警告使用橙色，失败使用红色，同时配合图标和文字，不只依赖颜色。
- 工作流步骤卡片与中间节点使用一致阴影。右侧参数卡片按内容高度悬浮，下面露出与画布连续的点阵背景。

### 4.3 执行结果

执行页必须回答“发生了什么、当前影响是什么、下一步能做什么”。页面包含节点进度、耗时、错误解释、操作按钮、结构化结果、诊断日志和产生的文件。普通用户不需要阅读原始终端输出。

## 5. 系统架构

### 5.1 前端与权限边界

React 和 TypeScript 负责界面、表单、画布和只读状态展示。WebView 不直接访问凭据、文件系统、SSH 或更新安装器。所有敏感操作通过类型化的 Tauri 命令边界进入 Rust 核心；命令参数在 Rust 侧再次验证。

### 5.2 Rust 核心模块

- 连接管理器：SSH 会话、主机指纹、超时、取消和错误分类。
- 系统能力检测器：发行版、包管理器、服务管理器、架构和命令能力。
- 模板引擎：模板版本、兼容条件、参数模型和系统族实现选择。
- 工作流运行器：状态机、条件分支、恢复点、节点重试和持久化。
- SFTP 文件层：流式上传下载、校验和和临时文件原子替换。
- 日志解析器：流式检索、分页、压缩日志和统一脱敏。
- 凭据保险库：Windows DPAPI 加密、按需解密和内存清理。
- 更新管理器：更新源探测、签名验证、下载、安装和失败恢复。

各模块通过明确数据结构通信，不向 UI 暴露库对象或原始连接句柄。远程目标通过适配器接口抽象，使后续 Windows OpenSSH 和网络设备支持不需要改写工作流核心。

### 5.3 本地数据库

SQLite 保存服务器非秘密信息、任务、工作流、执行记录、模板版本和主机指纹。数据库迁移必须可重放、可备份，并在升级失败时保留原数据库。秘密只保存引用，不直接写入普通表字段。

## 6. 数据目录与 C 盘约束

便携版默认使用程序旁的 `data` 目录。安装版首次启动要求用户选择数据根目录，并提供后续迁移功能。公开版本不能假设用户存在 D 盘。

数据根目录结构：

```text
data/
├─ app.db
├─ vault/credentials.bin
├─ logs/
├─ downloads/
├─ backups/
├─ templates/
├─ cache/webview2/
└─ updates/
```

当前开发机上的源码、依赖缓存、Cargo 构建产物、Node 包缓存、测试数据、安装包和更新包均配置到 `D:\Codex Project\轻量化SSH快捷工具` 内。首次选择数据目录前使用无持久化的 WebView；选定后通过 Tauri 的 WebView 数据目录接口将持久化缓存固定到 `<数据根目录>\cache\webview2`。Windows、WebView2 运行时本体或已安装工具产生的系统级数据无法完全禁止；发布前通过落盘审计验证应用自身不会偷偷写入默认 AppData。

数据迁移采用“复制到新目录 → 校验数据库和文件哈希 → 原子切换配置 → 用户确认后再清理旧目录”的顺序。失败时继续使用旧目录，不留下半迁移状态。

## 7. 凭据与安全

- 密码、私钥内容和私钥口令使用 Windows DPAPI 与当前 Windows 用户绑定后保存。
- 用户可导入私钥到加密保险库；配置导出默认排除秘密。
- 便携目录移动到其他电脑或 Windows 用户后，凭据不可解密，用户必须重新输入或重新导入。
- 凭据只在建立连接时按需解密，Rust 侧尽快清理明文缓冲区。
- 日志、错误、诊断包和遥测均通过统一脱敏器，禁止记录密码、私钥内容、口令和敏感参数。
- 删除、覆盖、停止服务、提权和回滚属于危险操作，执行前说明目标、影响和恢复方式并二次确认。
- 首版默认只启用现代 SSH 算法。未来为旧设备提供兼容模式时，必须显式警告且按服务器单独开启。

应用不采集账号、服务器地址、命令内容或执行日志到云端。首版不提供遥测；崩溃报告只能由用户主动导出脱敏诊断包。

## 8. 在线更新与发布渠道

客户端启动后按频率限制自动检查更新，发现正式版本后展示版本号、更新说明、发布时间和包大小，由用户确认后下载并安装。

GitHub Releases 是主更新源。魔搭同名公开模型仓库作为国内发布镜像，保存安装包、更新清单、签名和哈希文件，并通过公开单文件 API 供客户端读取；同名创空间只作为项目展示页。主源不可达时切换魔搭。若魔搭对二进制大小或格式有限制，发布流水线必须在正式发布前失败并阻止两个源出现不一致，不能悄悄省略安装包。

两个源的发布物必须来自同一次构建，具有相同版本、哈希和签名。更新管理器先验证 Tauri 更新签名，再验证 SHA-256 和版本策略。任何一项失败都删除临时更新包并保留当前版本。

GitHub 主仓库和魔搭镜像均使用项目名 QingzhouSSH。GitHub 负责源码、Issue 和正式 Release；魔搭负责国内镜像与备用下载。实际仓库命名空间在发布授权步骤使用用户登录账号创建，不属于运行时设计。

## 9. 错误处理

错误分为网络、认证、主机身份、权限、系统不兼容、参数、远程命令、文件传输、数据库、磁盘空间和更新错误。每类错误包含用户可读说明、技术详情、是否可重试、建议操作和诊断标识。

大输出必须流式处理并设置可配置上限。磁盘空间不足时停止下载或更新并删除不完整临时文件。数据库写入、配置更新和下载完成均使用临时文件加原子替换。应用异常退出后，下次启动把运行中任务标记为“中断，远程状态待确认”，不能假定失败或成功。

## 10. 测试与质量门槛

### 10.1 自动化测试

- Rust 单元测试：参数校验与转义、系统族匹配、状态机、日志脱敏、更新清单和签名拒绝。
- 组件测试：节点与分支、取消、节点重试、恢复点生命周期、SQLite 迁移和数据目录迁移。
- SSH/SFTP 集成测试：容器或虚拟机中的任务执行、文件校验、网络中断、权限不足和超时。
- Windows 端到端测试：首次启动、数据目录选择、凭据重启后解密、便携模式、安装、升级和卸载残留。

### 10.2 系统兼容矩阵

每个系统族至少验证一个受支持版本：

- Ubuntu / Debian：自动探测、核心任务自动测试、发布前实机验证。
- Rocky / Alma / Anolis：自动探测、核心任务自动测试、发布前实机验证。
- openEuler：自动探测、核心任务自动测试、发布前实机验证。
- 统信 UOS / 银河麒麟：自动探测和可自动化的核心任务，加发布前实机验证。

### 10.3 发布阻断条件

- 任意凭据或私钥内容进入日志。
- 更新签名或哈希校验可被绕过。
- 文件传输完成但校验和不一致。
- 应用声称任务已取消，但无法确认远程进程状态且没有警告。
- 应用自身在未授权情况下写入所选数据根目录之外。
- 任一首版系统族没有完成规定的发布前验证。

## 11. 实施里程碑

1. 安全连接骨架：Tauri 应用、数据根目录、SQLite、DPAPI、SSH/SFTP、主机指纹和系统探测。
2. 快捷任务与日志：系统状态、服务管理、日志检索、流式预览、下载和脱敏记录。
3. 工作流与恢复：节点画布、参数表单、条件分支、状态机、取消、重试、恢复点和回滚。
4. 发布与更新：安装版、便携版、签名更新、双源回退、GitHub 与魔搭同步、Apache-2.0 许可和公开文档。

每个里程碑必须通过对应测试和人工验收后才能进入下一个里程碑。

## 12. 明确不在首版范围

- 多服务器并行、循环和人工审批节点；
- Windows 远程主机、路由器、交换机和 NAS 的专用适配；
- 完整双栏 SFTP 文件管理器、目录同步和批量传输队列；
- 账号、云同步、团队权限、管理员模式和中央管理端；
- 交互式 SSH 终端；
- 静默自动安装更新。

这些能力通过远程适配器、模板版本和工作流节点接口保留迭代空间，但首版不实现占位功能或半成品入口。
