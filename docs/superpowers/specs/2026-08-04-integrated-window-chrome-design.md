# 轻舟 SSH 一体化窗口标题栏设计

日期：2026-08-04
状态：用户已确认视觉方向，等待书面规格复核

## 目标

移除 Windows 原生白色标题栏，使当前蓝色应用顶栏直接成为客户端最外层窗口顶部。用户不再看到“一个窗口里嵌着一套界面”的双层结构，同时保留桌面客户端应有的拖动、最小化、最大化/还原、关闭和边缘缩放能力。

## 方案比较

1. 保留原生标题栏，仅调整标题或颜色：实现风险最低，但仍保留双层窗口观感，不满足目标。
2. 用前端元素覆盖原生标题栏：缩放、DPI 或系统主题变化时容易露出原生边缘，也会形成两个控制区。
3. 使用 Tauri 无边框窗口并在蓝色顶栏内提供窗口控制：视觉完整，行为可控。采用此方案。

## 窗口结构

- Rust 创建主窗口时关闭原生 decorations，继续保持可缩放、最小尺寸 `960 × 640` 和 GUI 子系统。
- 蓝色 `.app-topbar` 顶到窗口四边，不再保留第二层顶部空白。
- 品牌区域和顶栏空白处作为拖动区域；双击拖动区域切换最大化/还原。
- 数据目录徽章保持原位置，但不参与拖动，避免点击或选择文字时误拖窗口。
- 右上角增加三个标准窗口按钮：最小化、最大化/还原、关闭。按钮使用现有 Phosphor 图标，不新增图片资源。
- 关闭按钮默认与顶栏融合，悬停时使用 Windows 用户熟悉的红色警示状态；其余按钮使用半透明高亮。
- 窄窗口时品牌文字可收缩，数据目录徽章优先截断；三个窗口按钮始终可见且保持固定点击面积。

## 行为与权限

- 顶栏使用 Tauri 官方 `data-tauri-drag-region` 处理拖动与双击最大化；前端通过 `@tauri-apps/api/window` 调用当前窗口的 `minimize`、`toggleMaximize` 和 `close`。
- Tauri capability 仅增加上述窗口操作所需的最小权限，不开放其他窗口或系统能力。
- 在非 Tauri 测试环境中，窗口控制适配层可被安全替换，页面本身不会因缺少原生窗口对象而崩溃。
- 每个窗口操作失败时不弹出原始技术异常；控制按钮保持可再次操作，避免客户端卡死。

## 测试与验收

- 前端测试先验证三个窗口按钮分别调用正确操作，并验证官方拖动区域标记存在。
- Rust/源代码契约测试验证主窗口关闭原生 decorations，仍保持 resizable 和最小尺寸。
- capability 契约测试验证只增加需要的窗口权限。
- 正式 Tauri 构建后实际启动 EXE，检查：原生白色标题栏消失；蓝色顶栏贴合最外层；窗口按钮可用；拖动、双击最大化和边缘缩放正常；内容区尺寸不回退。
- 生成新的本地测试包，不覆盖 r4；用户验证后再决定是否继续迭代。

## 不在本次范围

- 不改变首页、导航、卡片、日志检索或文件传输布局。
- 不连接远程服务器。
- 不发布 GitHub/魔塔版本，不修改在线更新版本号。
