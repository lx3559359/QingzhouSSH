# 轻舟 SSH：运维快捷任务与脚本中心设计规格

日期：2026-08-05  
状态：用户已确认设计  
参考项目：`F:\SSH工具开发` 中的运维工具、服务器维护快捷命令和只读排障 Runbook

## 1. 背景

当前客户端已经具备服务器管理、系统自动识别、8 个内置快捷任务、受控高级命令与脚本、日志检索、SFTP、工作流、执行历史和在线更新。现有快捷任务覆盖系统概览、磁盘、进程、服务和日志，但任务数量少，无法满足不熟悉 Linux 的个人用户进行日常巡检、故障排查和安全维护。

本次扩展把“快捷任务”升级为完整的运维工具中心。功能参考 `F:\SSH工具开发`，但不直接移植其 JavaScript 执行体系；所有任务继续进入当前 Rust 强类型执行、SSH、历史、脱敏和恢复体系。

## 2. 已确认的产品决策

- 采用全量范围：约 40 个单项任务、9 个组合巡检脚本以及个人脚本库。
- 使用 Rust 强类型任务引擎 V2，不建立第二套 JavaScript 命令执行体系。
- 仅使用当前 SSH 账号权限；允许 root 或 `sudo -n` 免密 sudo，不保存或传递 sudo 密码。
- 内置危险维护任务必须经过预演、二次确认、自动备份、执行后验证和可回滚流程。
- 脚本中心包含内置审核脚本和个人脚本库；个人脚本始终按高风险处理。
- 只读任务可以多选服务器批量执行；修改类任务一次只允许一台服务器。
- 结果首先展示中文结论、解释和建议，原始输出放在技术详情中，并可下载报告。
- 全部功能完成并验证后只生成一个新的本地测试包，不覆盖 r7，不自动发布到 GitHub、魔塔或在线更新源。

## 3. 目标用户与设计原则

主要用户拥有服务器地址和登录凭据，但不了解 Linux 命令、日志位置、服务管理器或发行版差异。产品需要让用户选择“想检查或处理什么”，而不是要求用户先知道命令。

设计原则：

1. 中文意图优先：界面描述操作目的、影响和建议，默认不展示命令正文。
2. 能力驱动：系统名称只参与分类，真正可用性以远端命令、服务管理器、容器运行时和权限预检为准。
3. 安全默认：只读与修改严格分离，未知状态不误报成功。
4. 可恢复修改：能安全恢复的修改必须先建立恢复点；无法提供可靠恢复的操作不进入内置目录。个人脚本无法自动推断修改目标，因此必须明确标记为“不可自动回滚”。
5. 单一执行体系：快捷任务、脚本、工作流和历史复用同一服务层、事件模型、取消语义和脱敏边界。
6. 有界执行：参数、输出、步骤、耗时、并发和本地/远端文件均有明确上限。

## 4. 范围与非目标

### 4.1 本期范围

- 系统、资源、存储、网络、安全、服务、日志、Web 和容器运维任务。
- 多步骤只读巡检与故障排查脚本。
- 个人脚本的创建、版本、参数、分类、收藏、导入导出和受控执行。
- 只读批量执行、单机修改、结构化结果、报告、恢复点和回滚。
- Debian、RHEL、openEuler 及已映射国产发行版的自动适配。

### 4.2 明确不做

- 交互式 SSH 终端、PTY、持续 stdin 或全屏 TUI。
- 保存或向远端传递 sudo 密码。
- 系统全量升级、任意软件安装、用户密码修改、SSH 配置自动修改。
- 一键关闭防火墙、清空规则或绕过服务器权限。
- 在线第三方脚本市场、动态任务插件或未签名任务包。
- 修改任务的多服务器并发执行。

## 5. 总体架构

现有 Rust 任务模块升级为任务引擎 V2，并继续由 `ExecutionService` 统一执行。

```text
快捷任务/脚本中心 UI
        |
        v
Task Catalog / Script Repository
        |
        v
参数校验 -> 能力与权限预检 -> 预演与影响摘要
        |
        v
恢复点创建 -> 受控步骤执行 -> 执行后验证
        |                         |
        v                         v
回滚服务                    结果解析与报告
        \_________________________/
                    |
                    v
          执行历史、事件与诊断
```

### 5.1 内置任务目录

内置任务编译进客户端。前端只能提交稳定任务 ID、版本和参数，不能提交命令模板或替换任务实现。目录负责：

- 稳定任务 ID 和版本。
- 分类、标题、用途、风险和预计耗时。
- 参数定义与默认值。
- 系统、命令、服务管理器、容器运行时和权限兼容条件。
- 预检、预演、执行、验证和回滚步骤。
- 输出限制、解析规则和中文建议。

### 5.2 个人脚本仓库

个人脚本不进入内置目录。脚本仓库保存在用户选择的数据根目录中，后端负责版本化、启停、导入导出和执行授权。脚本正文不进入浏览器存储、普通运行事件、诊断报告或确认弹窗。

### 5.3 批量协调器

批量协调器只接受只读任务和只读内置脚本。默认并发上限为 3 台服务器；每台服务器具有独立的预检、执行、取消、结果和失败状态。单台失败不终止其他服务器，但用户可以取消整个批次。

## 6. 任务定义 V2

任务定义需要表达以下信息：

```rust
struct TaskDefinitionV2 {
    id: String,
    version: i32,
    category: TaskCategory,
    title: String,
    description: String,
    risk_level: RiskLevel,
    estimated_seconds: u32,
    privilege: PrivilegeRequirement,
    parameters: Vec<ParameterDefinition>,
    implementations: Vec<TaskImplementationV2>,
    result_schema: ResultSchema,
}

struct TaskImplementationV2 {
    compatibility: CompatibilityPredicate,
    preflight_steps: Vec<TaskStep>,
    preview: PreviewDefinition,
    backup_plan: Option<BackupPlan>,
    execution_steps: Vec<TaskStep>,
    verify_steps: Vec<TaskStep>,
    rollback_plan: Option<RollbackPlan>,
}
```

具体字段名可以在实施时按现有 Rust 风格调整，但必须保持上述边界。命令模板继续跳过 IPC 序列化。

### 6.1 风险级别

- `safe`：只读取状态，不创建持久远端文件，不改变服务器。
- `caution`：只读为主，但可能短暂采样、创建临时文件或产生明显资源消耗，例如限量抓包。
- `dangerous`：修改服务、配置、网络、计划任务、权限、Swap 或容器状态。

### 6.2 权限要求

- `current_user`：当前账号即可运行。
- `root_or_passwordless_sudo`：账号为 root，或 `sudo -n true` 成功。
- 不支持需要交互输入密码的 sudo。

## 7. 功能目录

### 7.1 系统与资源

- 系统运行概览。
- CPU 压力诊断。
- 内存、Swap 与 OOM 检查。
- 进程资源排行、模糊查询和详情查看。
- 内核告警与错误。
- 启动、关机和重启历史。
- 时间与时区查询。
- 修改主机名。
- 修改系统时区。

### 7.2 磁盘与文件

- 磁盘容量、文件系统和 inode。
- 挂载状态。
- 磁盘 I/O 延迟。
- 大目录占用分析。
- 已删除但仍占用空间的文件。
- 文件权限与归属。
- Swap 查询、创建、启用、停用和移除。

### 7.3 网络诊断与维护

- 网卡、地址、错误计数和链路状态。
- TCP 状态和监听端口。
- 端口对应进程。
- IP、出口地址、路由策略和 MTU。
- DNS 解析检查。
- Ping、路径和网络连通性。
- HTTP 接口检测。
- TLS 证书和到期时间。
- UDP 综合检测。
- 限量抓包并下载到项目数据目录。
- hosts 映射管理。
- 服务器 IP 修改与超时自动回滚保护。

### 7.4 安全与防火墙

- SSH 登录、失败尝试和高权限账号检查。
- 防火墙状态和暴露端口。
- 放行防火墙端口。
- firewalld、UFW、nftables、iptables 能力识别。

### 7.5 服务、日志与计划任务

- 已安装服务清单。
- 失败服务及关联日志。
- 服务状态、启动、停止和重启。
- 服务开机自启策略。
- systemd timer 与 Cron 清单。
- 新增、停用、移除带工具标识的 Cron 任务。
- 现有日志关键词检索与智能日志页面联动。

### 7.6 Web 与容器

- Nginx/Apache 配置检查。
- HTTP、HTTPS 和 TLS 检测。
- Nginx 502/504 故障排查。
- Docker/Podman 运行时、容器、健康状态、资源和存储检查。
- 容器日志、配置和资源查看。
- 容器启动、停止和重启。

### 7.7 内置组合脚本

- 服务器综合健康巡检。
- CPU 高负载现场采集。
- 内存、Swap 与 OOM 排查。
- 磁盘空间与 I/O 故障包。
- 网络间歇性故障排查。
- SSH 登录安全审计。
- Web 502/504 故障包。
- Docker/Podman 容器故障包。
- 指定服务故障排查。

## 8. 参数与兼容性

参数类型在现有字符串、整数、布尔、枚举、绝对路径、服务名和时间范围基础上扩展：

- 主机或 IP。
- TCP/UDP 端口。
- 网卡。
- CIDR。
- 容器名或容器 ID。
- 文件权限模式。
- Cron 五段表达式。
- 单选与多选服务。
- 有界远端文件路径和有界本地项目内路径。

所有参数在 Rust 中验证，并通过安全 Shell 引用生成命令。任务定义不允许未知参数；枚举操作只能使用任务声明的固定值。

系统兼容以能力探测为准：

- Ubuntu、Debian、银河麒麟、UOS 映射到 Debian 系列。
- RHEL、CentOS、Rocky、AlmaLinux、Anolis 映射到 RHEL 系列。
- openEuler 保留独立系列。
- 服务管理识别 systemd 与传统 `service`。
- 防火墙识别 firewalld、UFW、nftables、iptables。
- 容器运行时识别 Docker 与 Podman。
- 缺少能力的任务灰显并说明缺少项，不猜测命令或包管理器。

## 9. 执行生命周期

内置危险维护任务固定使用以下状态：

```text
validating
-> preflighting
-> preview_ready
-> waiting_confirmation
-> backing_up
-> running
-> verifying
-> succeeded | failed | uncertain
-> rollback_available
-> rolling_back
-> rolled_back | rollback_partial | rollback_failed | uncertain
```

只读任务跳过确认和备份状态。个人脚本跳过自动备份和回滚状态，但必须在确认前明确显示“客户端无法自动恢复此脚本造成的修改”。批量任务为每台服务器保存独立状态，并聚合为批次状态。

取消只表示执行通道已确认停止。网络断开、应用崩溃或无法确认远端进程状态时记录为 `uncertain`，不能显示“已取消成功”或“执行失败且未修改”。

## 10. 预演、备份、验证与回滚

### 10.1 预演

危险任务的预演必须在远端重新读取当前状态，但不得修改服务器。预演结果展示：

- 目标服务器。
- 需要的权限。
- 将修改的对象。
- 修改前摘要和预期修改后状态。
- 备份方式和回滚能力。
- 验证方式和预计断连风险。

### 10.2 本地恢复数据

本地恢复数据使用：

- `<data-root>\backups\tasks\<execution-id>`：文件备份、状态快照和恢复元数据。
- `<data-root>\downloads\reports`：用户下载的 TXT/JSON 结果与批量汇总报告。

路径由后端生成，前端不能指定任意本地绝对路径。便携版仍通过 `portable.flag` 将数据放在程序旁的 `data` 目录。

### 10.3 远端短期恢复资产

主机网络、关键防火墙和其他断线后无法由客户端立即恢复的任务，可以创建远端短期恢复脚本。恢复目录必须：

- 由执行用户拥有，目录权限 `0700`、文件权限 `0600/0700`。
- 拒绝符号链接、路径穿越、已有文件覆盖和所有者不匹配。
- 文件名绑定执行 ID，内容带校验和和一次性消费标记。
- 在保留期限到期或用户确认清理后删除。

### 10.4 网络修改保护

修改 IP 或关键防火墙规则前必须先安排远端超时自动回滚。客户端应用修改后建立新连接并验证 SSH 可达性；只有验证成功才取消自动回滚。连接中断时保持自动回滚安排，并把本地状态标记为 `uncertain`，等待重新连接核验。

### 10.5 重复回滚

回滚操作必须幂等或明确拒绝二次消费。同一恢复点已经成功回滚后，不能再次应用。部分回滚需要保留未完成项及诊断信息，不得删除仍有用途的恢复资产。

## 11. 运维工具中心界面

快捷任务导航名称保持不变，页面内部升级为运维工具中心。

### 11.1 顶部与目录

- 单服务器选择和只读批量服务器选择。
- 任务搜索。
- 推荐、系统、存储、网络、安全、服务、Web、容器、脚本分类。
- 收藏和最近使用。
- 卡片显示用途、风险、兼容性、预计耗时和权限要求。
- 不兼容任务灰显并显示原因。

任务卡右键菜单只提供对象相关安全操作：查看说明、收藏/取消收藏、复制为个人脚本；不提供绕过确认或直接执行危险任务的入口。

### 11.2 任务流程

1. 选择任务和目标服务器。
2. 使用中文表单填写参数。
3. 运行能力、权限和参数预检。
4. 展示预演与影响摘要。
5. 只读任务运行；危险任务等待二次确认。
6. 展示中文结论、异常项、建议和技术详情。
7. 提供报告下载；成功修改提供回滚入口。

### 11.3 批量结果

批量面板按服务器显示等待、运行、正常、警告、失败、取消和状态不确定。支持取消整个批次、重试失败服务器和下载汇总报告。批量入口不接受危险任务。

## 12. 脚本中心

### 12.1 内置脚本

内置脚本编译进客户端，只读且不可直接修改。用户可以复制为个人脚本，复制后即脱离内置签名和安全级别，按个人高风险脚本处理。

### 12.2 个人脚本

支持：

- 新建、编辑、复制、删除和启用/禁用。
- 分类、标签、收藏和搜索。
- 不可变版本历史。
- 强类型参数变量。
- JSON 格式导入导出。
- 单服务器运行和执行历史。

个人脚本始终为 `dangerous`，即使内容看起来只读，也必须预检、显示行数/字符数/参数摘要、明确提示“不可自动回滚”并二次确认。脚本文本可以由用户在编辑器中查看，但确认弹窗、普通事件、日志、报告和诊断包只保存摘要。

个人脚本参数不直接替换脚本文本。后端把已验证参数映射为固定前缀的环境变量，例如 `QZ_PARAM_HOST`，再通过安全引用启动非交互 `sh`；脚本作者显式读取这些变量。参数名必须符合受限标识符规则，值不得改变 Shell 结构。

导入包必须具有固定格式版本、大小上限、脚本长度上限和参数数量上限；不得包含凭据、服务器配置、执行历史或本地绝对路径。静态扫描只用于提示高风险语法，不能把脚本误标为安全。导入完成后默认禁用，用户查看内容并主动启用后才能执行。

### 12.3 数据模型

- `script_definitions`：脚本身份、标题、分类、标签、收藏和启用状态。
- `script_versions`：不可变脚本正文、参数定义、摘要和创建时间。
- `script_runs`：引用脚本版本与现有执行记录。

删除脚本只标记定义不可用，不破坏旧历史所引用的版本。

## 13. 结果、报告与中文解释

任务实现使用有界机器标记或专用解析器生成结构化结果，不能仅靠前端猜测原始文本。结果包含：

- `normal`、`warning`、`failed`、`uncertain` 总体结论。
- 中文摘要。
- 关键指标或异常项。
- 下一步建议。
- 受限、脱敏的技术详情。
- 执行、备份、验证和回滚状态。

报告支持 TXT 和 JSON。报告不得包含服务器凭据、私钥、完整敏感参数、个人脚本正文或任意本地绝对路径。

## 14. 错误处理

错误主界面固定回答：发生了什么、服务器是否可能已改变、状态是否可确认、下一步怎么做、是否存在恢复点。

错误分类包括：

- 系统或命令不兼容。
- 当前账号权限不足。
- 参数验证失败。
- SSH/SFTP 网络中断。
- 备份创建失败。
- 远端执行失败。
- 执行成功但验证失败。
- 回滚成功、部分成功、失败或状态不确定。
- 批量任务中的单台服务器失败。
- 个人脚本导入、格式或版本校验失败。

主提示不能出现 `[object Object]`、Rust 堆栈或未解释的 Shell stderr。技术详情可以显示经过脱敏和长度限制的原始错误。

## 15. 安全约束

- 所有命令模板仅存在于可信后端代码或用户明确保存的个人脚本版本中。
- 内置任务参数不能插入命令结构；动态值必须验证并安全引用。
- 任务输出、事件、数据库摘要、报告和诊断包继续经过统一 redactor。
- 个人脚本不得进入 `localStorage` 或 `sessionStorage`。
- 批量执行并发、单步超时、总步骤数、总输出和报告大小均有上限。
- 抓包必须限制网卡、过滤器、数量、时长和文件大小，文件下载后清理受控远端临时文件。
- 只允许任务声明的恢复目标和验证步骤，前端不能提交回滚命令。
- 所有可控本地数据、缓存、测试和构建产物继续位于项目目录下，不写入 D 盘根目录或 C 盘 AppData。

## 17. 实施分解

虽然最终只交付一个测试包，编码和测试必须按以下内部阶段推进：

1. 任务引擎 V2、权限预检、状态机和兼容模型。
2. 只读单项任务和结构化结果。
3. 内置组合脚本、批量只读协调器和报告。
4. 危险维护任务、恢复点、验证和回滚。
5. 个人脚本仓库、版本、导入导出和界面。
6. 全量集成、安全、视觉、路径审计和本地打包。

各内部阶段必须保持测试通过，但中途不生成用户测试包，也不自动发布。

## 18. 完成标准

- 本规格列出的单项任务和 9 个组合脚本均可在支持的系统能力下运行。
- 不兼容、无权限和缺少命令均在执行前得到中文解释。
- 内置危险维护任务具备预演、确认、备份、验证和可验证回滚；无法可靠恢复的操作不得进入内置目录。个人脚本始终明确标记为不可自动回滚。
- 个人脚本具备版本、参数、导入导出和高风险执行闭环。
- 只读批量执行最多并发 3 台，修改类任务只能选择一台。
- 结构化结论、技术详情、TXT/JSON 报告和执行历史完整且脱敏。
- 所有自动化测试、Rust 格式检查、前端生产构建、原生 Tauri 构建、视觉验收和路径审计通过。
- 生成一个不覆盖 r7 的本地便携测试包，然后停止迭代等待用户验证。
